The grouped form for settings, visibility, account and edit screens. Row height,
separators and insets come from the system:

- iOS: SwiftUI `Form` and `Section`.
- Android: a scrolling Compose `Column` of `ListItem`s, grouped on `surface` with a 12pt radius.
- Web: Base UI `Form` and `Fieldset`.

`Form` fills its parent and scrolls, so give the parent a size
(`flex: 1` on a screen).

```tsx
<Form>
  <FormSection title="Privacy" footer="Only approved people see a private profile.">
    <SwitchRow label="Private profile" value={isPrivate} onValueChange={setPrivate} />
    <NavigationRow label="Who can see reviews" value="Club only" onPress={openAudience} />
  </FormSection>
</Form>
```

## Rows

- `SwitchRow`: label and a switch. The whole row toggles.
- `NavigationRow`: label and the current value. It opens a sheet or screen. On iOS the value sits before a chevron. On Android it shows as supporting text under the label (Material has no chevron).
- `ButtonRow`: a tinted action. `destructive` uses the system destructive role.

Don't put custom views inside a section. If you need a new row type, add it here.

## Forms with react-hook-form and zod

The rows are controlled (`value` + `onValueChange`) and don't know about any
form library. Keep form state in `react-hook-form`, validate it with a `zod`
schema through `zodResolver`, and bind each row with `Controller`:

```tsx
const schema = z.object({ privateProfile: z.boolean() });
const { control } = useForm({ resolver: zodResolver(schema), mode: "onChange", defaultValues });

<Controller
  control={control}
  name="privateProfile"
  render={({ field }) => <SwitchRow label="Private profile" value={field.value} onValueChange={field.onChange} />}
/>
```
