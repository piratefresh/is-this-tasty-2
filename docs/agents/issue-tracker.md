project and team.

## Conventions

- Create issues with a clear title and Markdown description.
- Read the full issue, its comments, labels, and status before acting.
- List relevant issues within this project, filtering by label or status.
- Apply triage labels using docs/agents/triage-labels.md.
- Use the team's existing workflow statuses; inspect them before changing
  status rather than assuming status names.
- Add findings and implementation results as issue comments when requested.
- Resolve issues using the team's completed or canceled status as appropriate.

When a skill says “publish to the issue tracker,” create a Linear issue
in this project. When it says “fetch the relevant ticket,” read the Linear
issue and its comments.

For wayfinding, use a parent issue for the map, child issues for tickets,
and Linear blocking relationships for dependencies. Preserve map order
in the parent description and assign claimed tickets to the driving dev.
